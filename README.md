# QRprint

**免安装的 Excel 批量标签打印工具。** 打开网页 → 选表格 → 直接打印，不需要安装任何软件，数据也不会离开你的设备。
支持 **二维码 / DataMatrix / Code 128 条形码** 三种码制。

### 👉 立即使用：<https://foodsaid.github.io/QRprint/>

> 也可以点右上角 **Code → Download ZIP**，解压后双击 `index.html` 本地打开，效果完全一样（连网络都不需要）。
> 手机浏览器同样可用。

## 特点

| | |
|---|---|
| **零安装、零依赖** | 整个工具就是一个 `index.html`，不需要 Node、Python、Excel 宏或任何插件 |
| **完全离线** | 页面用 CSP 禁止了一切网络请求。表格只在你本机的浏览器内存里解析，不上传、不落盘、不留存 |
| **三种码制** | 二维码（容错高、可存中文）、DataMatrix（同样是方的但更省地方）、Code 128（一维条码，兼容老扫描枪） |
| **通用，不限行业** | 码图内容叫 **Key**——物料号、资产编号、工单号、条码，任何一列都行 |
| **自动识别表头** | 认得 `Key` / `Item No.` / `物料号` / `编号` / `Code` 等几十种中英文写法；实在认不出会退回用第 1 列并给出提示 |
| **通用三段筛选** | 文本（选字段 + 包含/完全相等）、枚举（自动识别低基数列，下拉选值）、数值（`>` `≥` `=` `≠` `≤` `<`）——字段全部从你的表里动态生成，不写死任何业务列 |
| **去重与合计都由你定** | 按「Key + 你勾选的字段」去重；要不要把某个数值列相加，由你在「合计字段」里选，默认不启用 |
| **两种出纸方式** | A4 一页多枚（带等距裁切线，切刀不会错位）／标签打印机一枚一页（30×20 ~ 100×150 常用尺寸与自定义） |
| **版式自动排** | 每行个数默认「自动」，并实时显示每页几枚、一共几页；用条形码时还会算出最窄条宽，低于 0.19 mm 直接告警 |
| **界面可折叠** | 侧栏可整条左右收起让预览铺满；四个分节可上下折叠或一键全收 |
| **手机可用** | 窄屏自动切换成抽屉式设置面板，预览自动缩放到屏幕宽度 |
| **深浅色主题** | 跟随系统，也可手动切换 |

## 使用方法

1. **载入表格** —— 点击或拖放 `.xlsx` / `.xls` / `.csv`（≤ 60 MB）。
2. **选标签上要显示的字段** —— Key 必定显示；其余列自动列出，最多再选 6 个（勾选的字段同时参与去重）。
3. **选码制、纸张与版式** —— 二维码 / DataMatrix / 条形码；A4 多枚一页或标签纸一枚一页。
4. **筛选出这次要打的范围**，右侧实时预览，确认后点右上角 **打印**。

### 打印对话框里请务必检查

- 边距 → **无 / 默认**
- **关闭**页眉页脚
- **勾选**「背景图形 / Background graphics」——否则裁切线不会出纸
- 标签打印机：纸张尺寸选你实际的标签规格，缩放设为 **100% / 实际大小**

## 码制怎么选

| 码制 | 形状 | 能存什么 | 适合 |
|---|---|---|---|
| **二维码 (QR)** | 方 | 任意文本，含中文 | 默认首选，容错最高，手机也扫得动 |
| **DataMatrix** | 方 | Latin-1（不含中文） | 小标签，同样内容比二维码占地更小，电子/汽车行业常用 |
| **Code 128** | 长条 | 可打印 ASCII（不含中文） | 兼容只认一维码的老扫描枪、老 WMS |

用 Code 128 时注意：条码越长条纹越细。工具会按当前版式算出**最窄条宽**并显示；低于 **0.19 mm** 会标红，
这时候要么减少每行个数、要么放大码图、要么换成二维码 / DataMatrix。「自动」排版本身已经会避开这个区间。

三种码图都是矢量或点阵直出，打印时不会因为缩放而糊掉：DataMatrix 与 Code 128 输出 SVG（矢量），
二维码沿用 qrcode.js 的点阵并开启 `image-rendering: pixelated` 保持模块边界锐利。

## 对表格的要求

只要有一列能当 Key 就行，表头在前 30 行内任意位置都能找到。以下列会被特殊对待：

| 用途 | 可识别的表头写法（大小写、空格、`.`、`_`、括号均忽略） |
|---|---|
| **Key**（必需，码图内容） | `Key` `Item No.` `ItemCode` `Code` `ID` `No` `Barcode` `SN` `PartNo` `物料号` `物料编号` `料号` `编号` `编码` `代码` `条码` `序列号` `主键` … |
| 描述（默认勾选一次） | `Item Description` `Description` `ItemName` `Name` `Title` `物料描述` `描述` `品名` `名称` `说明` |

除这两项外**没有任何按表头名字写死的业务逻辑**：仓库靠通用的枚举筛选覆盖，
库存/数量要不要相加由你在「合计字段」里选（默认不启用，不选就让该列参与去重）。

- 一列都没认出来时，会取「前 30 行里第一行有 ≥2 个非空单元格的行」当表头、**第 1 列**当 Key，并在状态栏提示。
- 其余列原样列出，可自由勾选显示（最多 6 个）。整列为空的占位列会被自动剔除。多个工作表会一起解析。
- **筛选用的字段不写死**：载入后每列会自动判类型——不同取值 < 300 且有重复的算「枚举列」，
  非空值里 ≥80% 是纯数字的算「数值列」——再据此填充枚举/数值/合计三个下拉框。
  数字判定用的是整串严格匹配，`0303000001-00` 这类编号不会被 `parseFloat` 误认成数字。

**上限：** 单文件 60 MB、解析 200,000 行、单表 256 列 / 300 万单元格、预览渲染 2,000 枚。
（列数与单元格数的上限是防御性的，正常导出表远达不到；触发时状态栏会提示「已按上限截断」。）
超过 2,000 枚时预览只画前 2,000 枚，但**页数按全部数量统计**；点打印会问你是渲染全部再打，还是只打预览的部分。

## 隐私与安全

这类工具最常见的顾虑是「我的清单会不会被传走」。本项目从机制上排除这种可能。

### 数据不出本机

- 页面头部的 `Content-Security-Policy` 设为 `default-src 'none'; connect-src 'none'`，
  **浏览器层面禁止**任何 fetch / XHR / WebSocket / 外链资源，图片只允许本地生成的 `data:` 码图。
- 整个产物里**不存在任何网络调用能力**：全文搜不到 `fetch` / `XMLHttpRequest` / `WebSocket` /
  `sendBeacon` / `Worker` / `ServiceWorker`，也没有 `eval` / `new Function`。
- 没有任何 CDN、字体、统计、埋点。GitHub Pages 只负责把这一个 HTML 文件发给你。
- 表格解析与码图生成都在你的浏览器里完成，全程只在内存中，页面一关就没了。
  唯一写入本机存储的是深浅主题偏好（`localStorage` 一个键，值只可能是 `light` / `dark`）。

### 针对恶意表格的防护

一份 `.xlsx` 是攻击者可控的输入，所以按「打开的每个文件都可能是恶意的」来设计：

| 风险 | 处置 |
|---|---|
| **HTML / 脚本注入** | 单元格与表头一律通过 DOM 文本节点写入，全项目**零 `innerHTML` 写入**；CSP 额外开启 `require-trusted-types-for 'script'`，即使将来误加一处 HTML 写入也会被浏览器直接拦下 |
| **原型污染** | 所有以表格内容为键的字典均为无原型对象（`Object.create(null)`）；SheetJS 用 0.20.3（已含 [CVE-2023-30533](https://cdn.sheetjs.com/advisories/CVE-2023-30533) 修复） |
| **超大 `!ref` 拒绝服务** | `sheet_to_json` 会按声明的矩形整个铺开，与真实单元格数无关——一个几 KB 的文件声明 `A1:XFD1048576` 就是 170 亿格。展开前先把范围夹到 256 列 / 300 万单元格以内 |
| **ReDoS** | SheetJS 0.20.3 已含 [CVE-2024-22363](https://cdn.sheetjs.com/advisories/CVE-2024-22363) 修复；本项目自身的正则都作用在已截断（≤300 字符）的短串上 |
| **超长内容撑爆界面** | 单元格与**表头**都截断到 300 字符；文件 ≤60 MB、解析 ≤200,000 行、预览 ≤2,000 枚 |
| **CSV 公式注入** | 本工具只读不写，不会把内容再导出成表格，公式文本按普通文本打印 |

上述每一条都有对应的对抗性测试样例（原型污染表、注入表、900 列表），实测：
`Object.prototype` 零变化、注入内容全部以纯文本渲染、`window.__XSS*` 均未被置位、
页面内所有 `<img>` 的 `src` 只可能是自己生成的 `data:image/gif` 或 `data:image/svg+xml`。

### 内联依赖指纹

单文件方案没法用 SRI，所以把各段的哈希记在这里，便于核对是否被改动
（对 `<script>` 与 `</script>` 之间的内容按 UTF-8 计算）：

| 段落 | 字节数 | SHA-256 (base64) |
|---|---|---|
| SheetJS xlsx 0.20.3 | 951,971 | `2HJ+3EsM84THwnYlLN3a28HW12zshXXDxoIjxXShNQg=` |
| qrcode.js (Kazuhiko Arase) | 56,693 | `uAoMx2wD1+RB2HTfVw+PyT2VbBl21HbhUlg40bXNcbg=` |
| 码制模块（本项目） | 13,578 | `1D5m/rJuDAbWH/mzhUxe4jZh9+Jby5BSu+hQJU898q0=` |
| 应用逻辑（本项目） | 45,953 | `Xo99Peu3RKce7ncMmCqd/+y7sVirL+SSpUfkzhhvEaY=` |

> SheetJS 这份取自 npm 的 `@e965/xlsx` 镜像而非官方 <https://cdn.sheetjs.com>。
> 版本号高于两个 CVE 的修复版本，且已用构造的恶意文件实测未复现原型污染；
> 但若你所在环境有供应链合规要求，建议自行从官方源替换同版本文件。

### 已知残余风险

- **无法设置 `frame-ancestors`**：CSP 写在 `<meta>` 里时该指令无效，GitHub Pages 又不能自定义响应头，
  因此页面可被第三方站点嵌入。跨源 iframe 读不到你的数据，影响仅限点击劫持，
  但如果你在意，请自行部署到能设响应头的地方。
- **`script-src` 必须保留 `'unsafe-inline'`**：单文件方案的代价。防线因此完全依赖
  「绝不把不可信内容当 HTML 写入」，这也是上面开启 Trusted Types 的原因。
- **压缩炸弹**：`XLSX.read` 会先把整个工作簿解压进内存，60 MB 上限之内仍可能构造出高膨胀比的文件
  导致标签页内存吃紧。属于自伤范畴（你自己打开的文件），未做额外处理。

不放心的话，把仓库下载下来断网双击打开即可 —— 功能一模一样。

## 二次开发

仓库里只有一个 `index.html`，内部按顺序分成五段，都有中文注释标注：

| 段落 | 内容 |
|---|---|
| `<style>` 上半部分 | 界面外观（设计变量、顶栏、侧栏、折叠、移动端抽屉），可自由改 |
| `<style>` 下半部分 | **标签排版引擎** `.a4page` / `.grid` / `.cell` / `@media print`，尺寸单位与 JS 中的计算一一对应，改动会直接影响出纸效果 |
| 内联依赖 1/2 · 2/2 | [SheetJS xlsx](https://sheetjs.com) 0.20.3（Apache-2.0）与 [qrcode.js](http://www.d-project.com/) by Kazuhiko Arase（MIT），原样内联，未做修改 |
| 码制模块 | 本项目自己实现的 Code 128（ISO/IEC 15417）与 DataMatrix ECC200（ISO/IEC 16022），输出 SVG |
| 应用逻辑 | 解析 → 列类型判定 → 三段筛选 → 去重聚合 → 渲染 |

改版式看 `a4Metrics()`（单元格尺寸推算，`autoCols()` 与 `renderA4()` 共用，保证自动排版与实际出纸永远一致）
和 `renderLabels()`；表头别名在 `ALIAS`；各项上限见开头的
`MAXPREVIEW` / `MAXROWS` / `MAXFILE` / `MAXCACHE` / `MAXTEXT` / `MAXFIELDS` / `MAXENUM` / `MINBAR`。

### 码制模块的验证情况

Code 128 与 DataMatrix 是本项目实现的，离线跑了 589 项断言，全部通过：

- **Code 128**：107 个图案表的结构不变量（每个 11 模块、条宽和为偶、无重复）；
  12 个样本「编码 → 独立反向解码」往返一致（含校验位与终止符校验）；
  另外在浏览器里直接从渲染出的 SVG 条纹反解码，确认屏幕上那张图编的确实是 Key。
- **DataMatrix ECC200**：ASCII 编码测试向量；Reed–Solomon **校验子在 α¹..αⁿ 处全部归零**
  （这独立验证了 GF(256) 运算与生成多项式）；全部 15 种符号尺寸的放置**双射性**
  （每格恰好用一次、每个码字 8 位齐全）；L 形定位边与交替时钟边逐格核对；
  以及「位图 → 码字 → 文本」的完整往返。

Windows 版 Chrome 没有 `BarcodeDetector`，所以**没有用真实解码器做过端到端确认**。
投产前建议先用你自己的扫描枪试打一张。

### 重新拼装单文件时的坑

> ⚠️ **不要**把依赖源码放进 `String.replace()` 的替换串里 ——
> qrcode.js 内含 `case '$' :`，会被当成 `$'` 替换模式展开，把后面的 HTML 插进 JS 里，
> 造成那段脚本静默语法错误。用替换函数 `(...) => str`，并对各段做长度一致性校验。

之所以内联成单文件而不是拆成 `assets/` + `vendor/`：这样用户下载后双击就能用，
拆开后在 `file://` 协议下 Chrome 会把来源视为不透明源，CSP 的 `script-src 'self'` 会拦掉外部脚本。
