# QRprint

把 Excel 里的一列编号，批量打成带二维码的标签。

不用装软件，不用注册，打开网页就能用。你的表格不会上传到任何地方——所有事情都在你自己的浏览器里完成。

## 👉 [点这里直接用](https://foodsaid.github.io/QRprint/)

网页打不开、或者公司电脑不让上网？点 **Code → Download ZIP**，解压后**双击 `index.html`** 就行，功能一模一样。整个项目就这一个文件，拷到 U 盘、发微信都行。

手机浏览器也能用。

## 30 秒上手

1. **选表格** —— 拖一个 Excel 进去（`.xlsx` / `.xls` / `.csv`）。
2. **选标签上要印什么** —— 编号是必印的，其他列（品名、仓库、数量……）自己勾。
3. **点右上角「打印」**。

右边一直有实时预览，所见即所得。

## ⚠️ 打印前改 3 个设置

在浏览器弹出的打印窗口里：

- 「边距」选 **无** 或 **默认**
- **关掉**「页眉页脚」
- **勾上**「背景图形」（不勾的话裁切虚线印不出来）

用标签打印机的话，纸张尺寸选你实际的标签规格，缩放选 **100%**。

## 你的表格需要长什么样

只要**有一列是编号**就行，剩下的它自己认。

| Item No. | Item Description | Warehouse | In Stock |
|---|---|---|---|
| A-1001 | 白色无纺布 | WH01 | 250 |
| A-1002 | 铝合金支架 | WH02 | 80 |

- 编号那列叫什么都行：`Key`、`Item No.`、`物料号`、`料号`、`编号`、`Code`、`条码`…… 几十种写法都认得。真认不出来就用第一列，并且会告诉你。
- 表头不在第一行也没关系，前 30 行内都能找到。
- 多个 sheet 会一起读。

## 常见需求

- **只打某个仓库的** → 第 4 步「筛选范围」里选字段和取值，下拉框的内容是从你的表里自动生成的。
- **只打有库存的** → 同样在第 4 步，用数值条件 `> 0`。
- **手上有一串编号，只打这些** → 把它们粘进关键字框（空格或换行分隔），选「完全相等」。没找到的会告诉你是哪几个。
- **同一个编号出现多行** → 会自动合并成一张标签。想把数量加起来，在第 2 步选一下「合计字段」。
- **扫码枪是老式的、只认一维条码** → 第 3 步把码制换成「条形码」。还有 DataMatrix 可选（比二维码省地方）。

<details>
<summary><b>选哪种码？</b></summary>

<br>

| | 形状 | 能存什么 | 什么时候用 |
|---|---|---|---|
| **二维码** | 方 | 什么都行，含中文 | 默认用这个，容错最高，手机也扫得动 |
| **DataMatrix** | 方 | 不含中文 | 标签特别小的时候，同样内容比二维码占地少 |
| **条形码** | 长条 | 不含中文 | 老扫描枪、老系统只认一维码时 |

用条形码时，编号越长条纹越细。工具会算出最窄条宽显示在旁边，太细了会标红提醒你——这时候减少每行个数，或者干脆换二维码。选「自动」排版的话它本来就会避开。

</details>

<details>
<summary><b>数据会不会被传走？</b></summary>

<br>

不会，而且不是靠承诺，是靠机制：

- 页面用 CSP 在**浏览器层面**禁掉了一切网络请求。整个文件里搜不到 `fetch`、`XMLHttpRequest`、`WebSocket` 这些东西，也没有 `eval`。
- 没有 CDN、没有字体、没有统计、没有埋点。GitHub 只负责把这一个 HTML 文件发给你，之后就跟服务器没关系了。
- 表格只在内存里处理，页面一关就没了。唯一存在本机的是你选的深色/浅色主题。

最踏实的验证方式：下载下来，**断网**双击打开，一样能用。

另外也做了防恶意表格的处理（别人发来的 xlsx 也可能是坏的）：单元格内容一律当纯文本渲染、字典用无原型对象防污染、超大表格会被截断以免卡死浏览器。细节见下一节。

</details>

<details>
<summary><b>安全细节与已知风险</b></summary>

<br>

**针对恶意表格**（已用构造的攻击样例实测，不只是看代码）：

| 风险 | 处置 | 实测结果 |
|---|---|---|
| HTML / 脚本注入 | 全项目**零 `innerHTML` 写入**，内容只走 DOM 文本节点；CSP 开启 `require-trusted-types-for 'script'` | 含 `<img onerror>` / `<script>` / `<svg onload>` 的表格全部以纯文本渲染，注入标志位未置位 |
| 原型污染 | 以表格内容为键的字典全部是 `Object.create(null)`；SheetJS 0.20.3 已含 [CVE-2023-30533](https://cdn.sheetjs.com/advisories/CVE-2023-30533) 修复 | 表头与取值均为 `__proto__` / `constructor` 的表格，`Object.prototype` 零变化 |
| 超大 `!ref` 拖死浏览器 | 展开前把范围夹到 256 列 / 300 万单元格 | 修复前：2560 万声明单元格（文件只有 2 个真实单元格）要 12.3 秒、463 MB；xlsx 最大可声明 170 亿格 |
| ReDoS | SheetJS 0.20.3 已含 [CVE-2024-22363](https://cdn.sheetjs.com/advisories/CVE-2024-22363) 修复；自身正则只作用在 ≤300 字符的短串上 | — |
| 超长内容撑爆界面 | 单元格与表头都截断到 300 字符 | 5000 字符的值被正确截断 |

**各项上限**：文件 60 MB、20 万行、单表 256 列 / 300 万单元格、预览 2000 枚（超出时页数照常按全部统计，打印时可选渲染全部）。

**已知残余风险**：

- CSP 写在 `<meta>` 里时 `frame-ancestors` 无效，GitHub Pages 又不能自定义响应头，所以页面可被第三方站点嵌入。跨源 iframe 读不到你的数据，影响仅限点击劫持。在意的话请部署到能设响应头的地方。
- 单文件方案要求 `script-src` 保留 `'unsafe-inline'`，所以防线完全押在「绝不把不可信内容当 HTML 写入」上——这也是开 Trusted Types 的原因。
- `XLSX.read` 会先把整个工作簿解压进内存，60 MB 上限内仍可能构造高膨胀比的压缩炸弹。属于自伤范畴（你自己打开的文件），未做额外处理。

**内联依赖指纹**（单文件用不了 SRI，哈希记在这里便于核对是否被改动，对 `<script>` 与 `</script>` 之间的内容按 UTF-8 计算）：

| 段落 | 字节数 | SHA-256 (base64) |
|---|---|---|
| SheetJS xlsx 0.20.3 | 951,971 | `2HJ+3EsM84THwnYlLN3a28HW12zshXXDxoIjxXShNQg=` |
| qrcode.js (Kazuhiko Arase) | 56,693 | `uAoMx2wD1+RB2HTfVw+PyT2VbBl21HbhUlg40bXNcbg=` |

> SheetJS 这份取自 npm 的 `@e965/xlsx` 镜像而非官方 <https://cdn.sheetjs.com>。版本号高于两个 CVE 的修复版本，且已用恶意文件实测未复现原型污染；若你所在环境有供应链合规要求，建议自行从官方源替换同版本文件。

<details>
<summary><b>想改代码</b></summary>

<br>

`index.html` 内部按顺序分五段，都有中文注释：

| 段落 | 内容 |
|---|---|
| `<style>` 上半 | 界面外观，随便改 |
| `<style>` 下半 | **标签排版引擎**（`.a4page` / `.grid` / `.cell` / `@media print`），尺寸单位与 JS 里的计算一一对应，改了会直接影响出纸 |
| 内联依赖 1/2、2/2 | [SheetJS](https://sheetjs.com)（Apache-2.0）与 [qrcode.js](http://www.d-project.com/)（MIT），原样内联未改动 |
| 码制模块 | 本项目实现的 Code 128（ISO/IEC 15417）与 DataMatrix ECC200（ISO/IEC 16022），输出 SVG |
| 应用逻辑 | 解析 → 判列类型 → 筛选 → 去重 → 渲染 |

改版式看 `a4Metrics()`（`autoCols()` 与 `renderA4()` 共用它，保证自动排版和实际出纸一致）和 `renderLabels()`；表头别名在 `ALIAS`；各项上限在文件开头的 `MAX*` 常量。

**码制模块的验证情况**：离线跑了 589 项断言全部通过——Code 128 的图案表结构不变量 + 12 个样本的「编码 → 独立反向解码」往返；DataMatrix 的 Reed–Solomon 校验子在 α¹..αⁿ 全部归零、15 种符号尺寸的放置双射性、定位图形逐格核对、位图→码字→文本完整往返。另外在浏览器里直接从渲染出的 SVG 条纹反解码，确认屏幕上那张图编的确实是你的编号。

不过 Windows 版 Chrome 没有 `BarcodeDetector`，**没能用真实解码器做端到端确认**。投产前建议先用你自己的扫描枪试打一张。

> ⚠️ 重新拼装单文件时的坑：**不要**把依赖源码放进 `String.replace()` 的替换串里——qrcode.js 里有 `case '$' :`，会被当成 `$'` 替换模式展开，把后面的 HTML 插进 JS 里，造成静默语法错误。用替换函数 `(...) => str`，并对各段做长度校验。

之所以内联成一个文件而不是拆开：这样下载后双击就能用。拆开后在 `file://` 协议下 Chrome 会把来源当成不透明源，CSP 的 `script-src 'self'` 反而会把外部脚本拦掉。

</details>
